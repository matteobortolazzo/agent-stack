# Go Gotchas

Standard-library and language traps in this codebase that pass review and tests but fail silently at runtime.

## Rules

- When returning a slice from a helper that can be empty (e.g., slice-building helpers in JSON-serialization code paths), initialize with `make([]T, 0)` rather than `var s []T` or leaving it nil — Go's `json.Marshal` serializes nil slices as `null`, not `[]`, breaking stable JSON contracts (e.g., `cenci audit --json` where the default-safe case has no boundary weakenings). Initialize with `make([]T, 0, cap)` to ensure empty results marshal as an empty array `[]`. Add regression tests asserting the absence of `:null` in JSON output and presence of `:[]` for empty cases (see `watch/internal/sandbox/launcher/audit_test.go`, lines 566–576, for the pattern) (#588).
- Functions that internally construct `bufio.Reader` over an `io.Reader` field (e.g., `bufio.NewReader(e.Stdin)` inside the function) are unsafe to call more than once against the same underlying reader — the second call's fresh reader has its own independent buffer and silently observes `EOF` even when bytes for it remain in the first call's discarded buffer, causing piped input (e.g., confirmation answers) to be silently lost. Either provide a `WithReader` variant that accepts a caller-owned reader (e.g., `PruneWithReader`), or ensure callers construct a single shared reader upfront and pass it to every invocation (#629).
- When building a regex or matcher pattern by splicing strings from a data-driven collection (e.g., `SupportedAgents`), guard against empty collections with an init-time panic (an empty slice silently degenerates to mismatches or over-match in deletion-critical paths like `sandbox prune`), and escape each element with `regexp.QuoteMeta` before joining (unescaped metacharacters in a future element would silently broaden the match instead of erroring). See `sandbox.go`'s `sandboxNamePattern`, `homeVolumePattern`, and `agentCLIVolumePattern` builders (#528).
- `os.IsNotExist`/`errors.Is(err, fs.ErrNotExist)` only classify filesystem-call errors — they never match an `os/exec` error. To handle a missing input file for an external command, `os.Stat` the path yourself first; don't infer it from the command's exit error.
- Closed-set enums must be audited as a group, in two directions. (1) Within one switch: when a new state/enum replaces a previously-collapsed failure mode (e.g. `CredentialProbePresent/Missing/Error` replacing "present or error → absent"), audit every branch including `default`/fallback for silently reproducing the original collapse — a default that maps unrecognized values to the "safest-looking" case defeats the point of distinguishing failure classes (#598). (2) Across functions: when adding a value to an enum already handled by multiple independent functions (e.g. `Posture.Dind.Source`, rendered by both `WriteText` and `WriteExplanation`), grep for every switch/branch over that enum and update them consistently — in #627 `WriteExplanation`'s dind switch missed the newly-added `DindSourceUnknown` case that `WriteText` handled, because the independent switches were not reviewed as a coordinated group (#627). Both risks are invisible to tests of normal cases: assert fallback rendering explicitly (e.g. `credentialStatusText`'s switch-default rendering distinct text per probe class), not just the absence of errors.
- Functions that return a single boolean to classify a git/command outcome must never collapse 'legitimate false answer' and 'command failed' into the same boolean value — the boolean alone cannot represent both. Example: an earlier version of `isAncestor(dir, ancestor, descendant) bool` returned `err == nil`, treating both `git merge-base --is-ancestor` exit code 1 (a normal, successful "not an ancestor" answer) and exit code ≥2 or context-deadline timeout (genuine command error) as the single `false` value, making it impossible to distinguish whether the ancestor check truly failed or whether git itself errored. Change to return `(bool, error)` — let callers distinguish legitimate-but-false (err=nil, bool=false) from genuine failure (err≠nil). This matters especially in gating/safety decisions where conflating failure classes silently breaks invariants (#822).
- `exec.CommandContext(ctx, ...)` + `CombinedOutput()` or `cmd.Output()` under a context timeout does NOT fully bound wall-clock time without also setting `cmd.WaitDelay`. When the context deadline expires, the direct child process is killed, but `cmd.Wait()` can still block indefinitely if a grandchild process (ssh, a credential helper, git-remote-https) inherited the stdout/stderr pipes and keeps them open. The timeout bounds only the command start time and execution duration, not its termination. Set `cmd.WaitDelay` on every `exec.Cmd` used with output-capturing functions under a context deadline to ensure the process fully terminates within the deadline (#822).
- When building glob/regex patterns for path matching (e.g., `matchesProtected` deny-list matchers), distinguish between anchoring for exact match vs. directory-prefix matching — a fully-anchored pattern (`^pattern$`) will not match directory prefixes with trailing slashes even if semantic intent was to match all paths under that directory. If config entries like `"watch/internal/sandbox/"` are meant to match as directory prefixes, the matcher must strip the trailing slash before building the pattern OR append a `.*` to treat the slash as a prefix marker: `"watch/internal/sandbox/"` → `^watch/internal/sandbox/.*$` or similar. Test directory-prefix patterns explicitly to verify they match both `"watch/internal/sandbox/file.go"` and nested subdirectories. Unanchored prefix matching silently renders security-relevant denylists inert — the config looks correct but matches nothing (#824).
- When decoding JSON config into a Go struct with `json.Unmarshal`, Go's `encoding/json` package performs case-insensitive field matching as a fallback: if a JSON key doesn't exactly match a struct field's tag, the decoder will match it case-insensitively to any tagged field (e.g., `{"Planning":{"Autonomy":"lean"}}` will decode successfully even though the schema requires exact-case lowercase `planning`/`autonomy`). In security-critical gates that depend on config key validation (e.g., an authorization denial rule keyed on a specific config field), this fallback can silently accept malformed or incorrect configs intended to be rejected. For gates that must enforce exact-match key validation, decode into an explicit `map[string]json.RawMessage` and perform exact-match key lookups (`m["planning"]` not `m["Planning"]`), or use a strict custom unmarshaler that errors on unknown keys. Do not rely on struct-tag JSON decoding to enforce key-name invariants in security-relevant paths (#851).
- When extending an existing validation mechanism to a new call site or code path (e.g., applying a field-validation regex to a new field-read location), audit all existing call sites of the reference implementation to identify validation guards that apply to the field (e.g., a `^[0-9a-fA-F]{7,40}$` pattern guarding a git commit SHA before it reaches `exec` argv). Replicate those guards at every new call site consistently — partial replication where validation covers some paths but not others silently reopens the vulnerability the guard was designed to prevent (e.g., argument-injection via a leading `-` in an unvalidated SHA). Grep for all references to the guarded field before finalizing the extended mechanism. A silent omission of validation at a new call path defeats the hardening of the reference path and can only be caught by explicit regression testing or code review (#851).
- When using test fixtures that modify PATH — especially `installFakeGH` which replaces PATH wholesale — understand that full replacement breaks multi-tool shell pipelines (e.g., `yes | tr | head`) because standard utilities disappear from the environment. The pipeline then emits a short "command not found" error instead of the intended large payload, and a test assertion that doesn't validate output length or content will silently pass with wrong behavior. Always use `installFakeGHOnPath` (prepends to PATH) for tests that depend on shell-utility availability, or validate pipeline output explicitly (length, substring, absence of "not found") to catch silently-truncated results. See `collect_test.go`'s bounded-output regression tests that fixed this pitfall (#852).
- When using pointer fields (`*T`) to distinguish an absent/nil GraphQL response field from an explicit false value (the dispatch/config.go absent-vs-false pattern), be aware that a nil response from a successful fetch (e.g., `pullRequest: null` when the PR is deleted/inaccessible, zero exit, no top-level `errors[]`) looks identical to an uninitialized "not yet fetched" sentinel where both fields are nil. Use an additional explicit boolean flag (e.g., `Probed bool`) set to true whenever the fetch runs, to disambiguate the two cases. A nil response without the disambiguator will silently pass as if the fetch never happened, leaving the gate dependent on stale or missing sentinel values (#854).
- When searching for a query parameter within a URL string by substring (e.g., extracting `page=N` from a pagination URL), anchor the search to the parameter separator (`&page=`) not the bare parameter name (`page=`). A bare substring search will match the parameter name as a substring of other parameters (e.g., `page=` appears inside `per_page=100`), silently returning the wrong value and causing pagination to fetch the wrong page. Use `strings.Index(url, "&page=")` or equivalent anchored patterns; manually parse with `net/url` and `Query().Get()` to avoid this collision entirely (#855).
- When splicing dynamic values into git/exec command arguments — even if the current call site has only fixture-controlled, trusted inputs — add defensive validation that fails loudly on suspicious patterns (e.g., leading `-` that would be misparsed as a flag). The validation documents the assumption for future maintainers and prevents silent misbehavior if a call site ever uses external input. Pair this with explicit `--` separators where the command parser supports them to anchor positional vs. flag arguments (#855).
- In test fixtures that spawn a subprocess via a shell script (e.g., a fake `gh` command shim used in tests), use `exec <command>` to replace the shell process entirely, never bare `<command>` on its own line. A bare subprocess like `sleep 5` forks the command as a child of the shell process; when the parent context is cancelled or `Cmd` is killed, `Process.Kill` only reaches the direct child (the shell), leaving grandchild processes orphaned and holding stdout/stderr pipes open. This defeats deadline/cancellation testing for code paths verifying process termination behavior. Use `exec` to ensure the subprocess is PID-1 of the spawned process, so it terminates immediately when the parent kills it. Confirmed timing difference: ~51ms (with `exec`) vs ~5.0s (bare subprocess holding pipe open). This affects any test using script-based fakes that simulate timeout/cancellation or WaitDelay behavior (#886).
- When implementing a paginated API loop (GraphQL cursors, REST page numbers, or offset-based traversal), wrap the entire loop with a single shared `context` deadline — not just individual page-fetch calls with per-call timeouts. A per-call timeout (e.g., 60s per page) allows the overall operation to exceed the intended bound significantly (e.g., 20 pages × 60s = 1200s total for what should be a 60s operation). Create the context with the desired overall deadline before entering the loop, and pass it to every page-fetch subprocess call; when the deadline expires, the loop exits immediately and the context is cancelled at that outer boundary, not at the per-call level. Pair this with `cmd.WaitDelay` to guarantee process cleanup completes within the deadline. Pagination loops are especially susceptible to this because a single slow or timing-out page can compound across the loop depth (#881).
- When decoding JSON objects into Go structs where the JSON value can be `null` (GraphQL responses, REST APIs with optional fields), always use pointer fields (`*T`) not value fields (`T`) — Go's JSON decoder will silently zero-initialize a value-type field when the JSON value is `null` or missing, making `null` indistinguishable from an uninitialized zero-value. This is dangerous in gating code where the distinction matters: a `null` repository field (representing "unavailable") becomes indistinguishable from zero-value (representing "verified absent"). To distinguish all three states (null from API, zero-value, field with data), combine pointer fields with an explicit presence flag (e.g., `Probed bool`), following the #854 pattern. This gotcha affects any nullable object in a JSON-decoded struct; it is especially invisible because the JSON decode succeeds (zero exit), there are no top-level `errors[]`, and the struct field silently accepts the wrong value (#881).
- `os.MkdirAll(dir, mode)` does NOT enforce (or tighten) the mode on a pre-existing directory — if the directory already exists with looser permissions (e.g., inherited from an older code version, or a shared `--state-dir` with lenient setup), those permissions persist unchanged. To enforce a specific mode unconditionally on a security-relevant directory, call `os.Chmod(dir, mode)` immediately after `MkdirAll` with the same error wrapping. This applies anywhere a directory must always have a specific mode regardless of pre-existence: state dirs, temp dirs, credential storage, log dirs, etc. A mode-enforcement assumption hidden in a single `MkdirAll` call is a silent permission escalation if the directory ever predates the code or is shared across privilege boundaries (#975).
- When using `docker/podman inspect --format` to read a container's environment variables, filter the desired variable server-side in the Go template itself, never by dumping the full `.Config.Env` into the launcher process and filtering client-side in Go. The full env can carry secrets (e.g., `CONTEXT7_API_KEY`, `OPENAI_API_KEY`) that have no business transiting the launcher process's memory unnecessarily. Use server-side filtering patterns already established in the same package: e.g., `{{range .Config.Env}}{{if eq (index (split . "=") 0) "CENCI_SANDBOX_PLUGINS"}}{{.}}{{end}}{{end}}` (which uses `split` to extract the key and filters only the desired entry). The `split` function is available in the docker/cli inspect template funcmap; check docker/cli's `templates/templates.go` if extending the funcmap in the future (#1002).
- When using `exec.CommandContext(ctx, ...)` on best-effort, non-blocking probes (e.g., a drift-detection check that must never stall the main attach path), pair the context timeout with a bounded `cmd.WaitDelay` to ensure the process fully terminates within the deadline, and document the timeout constant's purpose. A context deadline alone bounds only the command start time and execution duration, not its cleanup — a grandchild process holding stdout/stderr pipes open can block indefinitely after the child is killed. Set both `cmd.WaitDelay` and a documented, scoped timeout constant (e.g., `const inspectContainerSandboxPluginsTimeout = 3 * time.Second` with a comment explaining why this probe can't block the caller). Establish a per-probe convention matching the package's existing patterns (e.g., `gitTimeout` in `internal/dispatch/mainsync.go`), and ensure timeout expiry resolves gracefully (no blocking error, just a degraded probe result) rather than as a hard failure (#1002, #825, #852).
- When a single PR adds multiple independent JSON decoders for the same field (e.g., a strict reader `QueryPlanningAttended` and a lenient dispatch-pass reader `resolvePlanningAttended` for the same `planning.attended` bool), any Go stdlib decode gotcha fixed in one decoder must be explicitly verified and replicated in every other decoder of that field in the same change. The gotcha that `encoding/json.Unmarshal` treats a JSON literal `null` into a non-pointer bool as a silent no-op (`err == nil`, value remains at zero-value `false`) is especially easy to fix in one path and overlook in a sibling path — the mistake silently defeats the intended narrowing behavior of the field with zero log output, making it invisible to tests of normal cases. Grep the entire change for all decoders/unmarshalers of the same field and audit each one against the fixed reference decoder. Do not assume "unmarshal will error" applies equally across readers; verify each one's error/success paths explicitly (#1086).
- Go filenames matching `*_<GOOS>_test.go` or `*_<GOARCH>_test.go` (where `<GOOS>` and `<GOARCH>` are Go's recognized OS/arch identifiers like `linux`, `arm`, `amd64`) are treated as implicit build constraints and silently excluded from builds on non-matching platforms — `go list -json` exposes these as `IgnoredGoFiles`, but no error is emitted at build time. A test file named `babysit_arm_test.go` would be silently excluded from every non-arm CI runner with zero test coverage, zero error, and zero indication the file exists. Avoid the suffix by renaming to a neutral pattern (e.g., `babysit_arming_test.go`) and document the reason in the file's header comment if the name change is non-obvious to future readers (#1094).
- When implementing failure-path cleanup keyed off a file pre-existence or post-deletion check (e.g., "if file existed before the attempt, delete it on failure"), audit for concurrent-writer races where one operation's cleanup could delete another concurrent operation's freshly-written state. Example: two concurrent arms race on the same key, and one's failure-cleanup deletes a pre-existing state file; the other operation's success writes a fresh state file and arms a guard based on that file, but that fresh file is then silently deleted by the first operation's cleanup, leaving the guard disarmed. Instead of existence-check-based cleanup, use atomic check-then-act operations, per-operation cleanup paths, or an explicit cleanup gate (e.g., `wasArmedByMe` flag) to ensure cleanup never deletes freshly-written state from a concurrent operation. Write explicit regression tests exercising the concurrent-arm race scenario where one fails and one succeeds, verifying no silent disarmament occurs (#924).
- When implementing a bounded-subprocess helper (e.g., `execRuntime`, `execGit`, `execArmTmux`) that uses `cmd.Run()` or `cmd.Wait()` under a `context.WithTimeout` deadline, **you must capture `ctx.Err()` yourself immediately after the subprocess call returns, before any deferred `cancel()` fires, and `errors.Join` it into the error**. Go's `os/exec` does NOT automatically wrap `ctx.Err()` into the returned error when the deadline fires mid-call — `cmd.Wait()` returns a plain `*exec.ExitError` (e.g. "signal: killed") with no indication the context was the cause. Similarly, a `cmd.WaitDelay`-triggered kill (lingering grandchild holding pipes open) returns bare `exec.ErrWaitDelay`, never joined with the deadline. Callers checking `errors.Is(err, context.DeadlineExceeded)` to classify a real timeout will silently miss this case. The pattern: capture `ctx.Err()` right after `cmd.Run()`/`cmd.Wait()` returns (before deferred cancel can change it to `context.Canceled`), check both `ctx.Err() == context.DeadlineExceeded` and `errors.Is(err, exec.ErrWaitDelay)`, and `errors.Join` `context.DeadlineExceeded` into the returned error when either condition is true. See working reference implementations: `watch/internal/babysit/gh.go` and `watch/internal/dispatch/gh.go` (pattern from #886), and `watch/internal/hostrepo/resolve.go`'s `classifyExecTimeout` helper (pattern applied to new bounded-subprocess sites in #1095).
- On Linux, `net.Listen("unix", "")` does NOT fail closed — the kernel autobinds into the abstract namespace (e.g., `@3855a`), producing a listener with no filesystem permissions at all, connectable by any local process in the same network namespace. This is asymmetric with `net.Dial("unix", "")`, which fails with `errMissingAddress` on empty paths. Do not assume network primitives behave symmetrically between dial-side and listen-side, or by analogy with other address families (e.g., TCP empty-address behavior). Before relying on any socket primitive's behavior in a security-gating decision, empirically test it: a two-line `go run` repro can catch assumptions that silently fail at runtime. When guarding against autobind or other unintended bindings, explicitly reject empty socket paths before calling `net.Listen` rather than relying on assumed failure-closed semantics (#1147).
